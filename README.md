<span id="en">RFSoC 4x2 QSFP28 IBERT</span>
===========================

Bit-error-rate test and eye scans of the RFSoC 4x2 (XCZU48DR-FFVG1517-2-E) QSFP28 port: **four GTY lanes at 25.78125 Gb/s** (the 100GBASE-SR4 / CAUI-4 lane rate), PRBS7 .. PRBS31 from the transceivers' own generators and checkers, per-lane error counts read through a VIO, and **2-D eye scans of every receiver through In-System IBERT** in the Vivado hardware manager. JTAG only, no PS software.

The test setup is a 100GBASE-SR4 QSFP28 optical module (Intel SPTSBP2CLCKV) in optical self-loopback: each lane's transmitter comes back on its own receiver. The GTs' near-end PMA loopback is selectable for a check without a module.

　

## Why not the IBERT IP

The QSFP28 reference clock of the RFSoC 4x2 is 156.25 MHz (MGTREFCLK0 of quad 128, AA33 / AA34). 25.78125 Gb/s is 165 times that, which the QPLL reaches only in fractional-N mode. The IBERT UltraScale GTY IP offers integer multiples only (161.1328125 MHz at this rate), so with this board's clock it could run the module's lanes at 25.0 Gb/s at best, outside the SR4 module's CDR range. This design builds the equivalent from the GT wizard instead:

* **Transceivers**: the GT wizard settings of the CMAC in [rfsoc4x2_100g_udp](https://github.com/uceeyuf/rfsoc4x2_100g_udp) (CAUI-4 preset, raw 80-bit data), proven on the same pins: QPLL0 fractional numerator 8388608 / 2^24 = 0.5, the reference routed north to the cage's channels X0Y4..X0Y7 (quad 129).
* **Patterns**: the GTs' PRBS generators and checkers (TXPRBSSEL / RXPRBSSEL), selected from the VIO; one forced error per lane on request.
* **Counting**: per lane, in the RX user clock (322.27 MHz, 80 bits a cycle): cycles with the checker locked, cycles with an error (one or more bits; at a low BER one bit each), lock losses. A snapshot request copies all counters at once; the VIO reads them while they are held.
* **Eye scans**: the In-System IBERT core on the four channels' DRP; its default settings are LPM equalization and the TX swing 11000b, changeable from the hardware manager.
* **QSFP28 sideband**: ResetL high, LPMode low (high power: the lasers on), ModSelL high (no I2C); ModPrsL and IntL are read in the VIO.

　

## Build and Run

Vivado 2023.2. The prebuilt bitstream and probes file are in `prebuilt/`, so the board can be tested without building (Vivado Lab Edition is enough):

```
git clone https://github.com/uceeyuf/rfsoc4x2_ibert.git
cd rfsoc4x2_ibert
vivado -mode batch -source tests/ibert_test.tcl -tclargs 60               # through the QSFP28 module, PRBS31, 60 s
vivado -mode batch -source tests/ibert_test.tcl -tclargs 10 0 31 eye      # ... then a 2-D eye scan of each lane
vivado -mode batch -source tests/ibert_test.tcl -tclargs 10 2             # GT near-end PMA loopback (no module needed)
```

Arguments: seconds, loopback (0 through the module, 2 near-end PMA), PRBS (7, 9, 15, 23, 31), `eye`, `noprog`. The script programs the FPGA, sets the pattern and the loopback, resets the transceivers, prints every second per lane the locked state, the checked rate, the errors and the BER, then forces one error per lane and checks that each lane counts it; with `eye` it writes `out/eye_lane<l>.csv`. The output is also in `out/ibert_test.txt`. In the Vivado GUI the same four channels appear under Serial I/O Links (In-System IBERT) for eye scans and analog settings.

Build from source (creates `build/`, copies the result to `prebuilt/`):

```
vivado -mode batch -source scripts/build.tcl -tclargs 16
vivado -mode batch -source scripts/program.tcl
```

| Directory      | Contents |
| :------------- | :------- |
| `rtl/`         | `fpga.v` (top: clocks, transceivers, In-System IBERT, counters, VIO) |
| `ip/`          | the GT wizard at 156.25 MHz, In-System IBERT, the VIO (Tcl) |
| `constraints/` | pins and clocks |
| `scripts/`     | `create_project.tcl`, `build.tcl`, `program.tcl` |
| `tests/`       | `ibert_test.tcl` |
| `prebuilt/`    | `rfsoc4x2_ibert.bit`, `rfsoc4x2_ibert.ltx` |

<span id="cn">RFSoC 4x2 QSFP28 IBERT</span>
===========================

RFSoC 4x2（XCZU48DR-FFVG1517-2-E）QSFP28 口的误码率测试和眼图：**4 路 GTY，每路 25.78125 Gb/s**（100GBASE-SR4 / CAUI-4 的单路速率），PRBS7 .. PRBS31 用收发器自带的发生器和校验器，每路误码计数经 VIO 读出；**每个接收端都能通过 In-System IBERT 在 Vivado 硬件管理器里扫二维眼图**。只用 JTAG，不需要 PS 软件。

测试环境是 100GBASE-SR4 QSFP28 光模块（Intel SPTSBP2CLCKV）光自环：每一路的发送回到它自己的接收。也可以选 GT 的近端 PMA 回环，不插模块先自检。

　

## 为什么不用 IBERT IP

RFSoC 4x2 的 QSFP28 参考时钟是 156.25 MHz（quad 128 的 MGTREFCLK0，AA33 / AA34）。25.78125 Gb/s 是它的 165 倍，QPLL 只有在小数分频模式下才能得到。IBERT UltraScale GTY IP 在这个速率下只接受整数倍（161.1328125 MHz），用这块板的时钟最多只能跑到 25.0 Gb/s，超出 SR4 模块 CDR 的锁定范围。所以这里用 GT wizard 搭出等效的测试：

* **收发器**：沿用 [rfsoc4x2_100g_udp](https://github.com/uceeyuf/rfsoc4x2_100g_udp) 中 CMAC 的 GT wizard 设置（CAUI-4 预设、RAW 80 bit 数据），在同一组引脚上已经实测可用：QPLL0 小数分子 8388608 / 2^24 = 0.5，参考时钟向北走到 QSFP 笼子的通道 X0Y4..X0Y7（quad 129）。
* **码型**：用 GT 自带的 PRBS 发生器和校验器（TXPRBSSEL / RXPRBSSEL），由 VIO 选择；每路可以单独注入一个错误。
* **计数**：每路在 RX 用户时钟（322.27 MHz，每拍 80 bit）下统计：校验器锁定的拍数、出错的拍数（一个或多个比特；误码率低时每拍一个比特）、失锁次数。快照请求一次复制所有计数器，VIO 在保持期间读取。
* **眼图**：In-System IBERT 核接四个通道的 DRP；默认 LPM 均衡、TX 摆幅 11000b，可以在硬件管理器里改。
* **QSFP28 控制脚**：ResetL 拉高，LPMode 拉低（高功率模式：激光打开），ModSelL 拉高（不用 I2C）；ModPrsL 和 IntL 从 VIO 读。

　

## 构建与运行

Vivado 2023.2。`prebuilt/` 里有现成的位流和探针文件，不构建也能直接上板测试（Vivado Lab Edition 就够）：

```
git clone https://github.com/uceeyuf/rfsoc4x2_ibert.git
cd rfsoc4x2_ibert
vivado -mode batch -source tests/ibert_test.tcl -tclargs 60               # 经过 QSFP28 模块，PRBS31，60 秒
vivado -mode batch -source tests/ibert_test.tcl -tclargs 10 0 31 eye      # ……之后每路扫一次二维眼图
vivado -mode batch -source tests/ibert_test.tcl -tclargs 10 2             # GT 近端 PMA 回环（不需要模块）
```

参数依次是：秒数、回环（0 经过模块，2 近端 PMA）、PRBS（7、9、15、23、31）、`eye`、`noprog`。脚本下载 FPGA，设置码型和回环，复位收发器，每秒逐路打印锁定状态、校验速率、误码和误码率，最后每路注入一个错误并确认各自计到；加 `eye` 时写出 `out/eye_lane<l>.csv`。输出同时写到 `out/ibert_test.txt`。在 Vivado 图形界面里，同样的四个通道出现在 Serial I/O Links（In-System IBERT）下，可以扫眼图、调模拟参数。

从源码构建（生成 `build/`，结果复制到 `prebuilt/`）：

```
vivado -mode batch -source scripts/build.tcl -tclargs 16
vivado -mode batch -source scripts/program.tcl
```
